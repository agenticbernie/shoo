# Shoo Technical Evaluation Framework

- Version: 0.1
- Status: Accepted — Gate 9
- Owner role: AI Systems Architect / QA Architect / Staff Platform Engineer
- Dependencies: Architecture Fitness Tests; Implementation Testing Strategy; Product Metrics
- Assumptions: Controlled fixtures and consented beta samples can represent OpenCode-to-Codex continuation
- Unresolved questions: Final embedding model and representative corpus size
- Last decision: Evaluate the pipeline by authority, retrieval, context utility and recovery—not vector similarity alone
- Next action: Build the R0 harness and freeze the first gold dataset version

## Evaluation layers

| Layer | Measures | Primary failure prevented |
|---|---|---|
| Capture | event completeness, duplicate rate, ordering convergence | Missing/duplicated session truth |
| Extraction | typed precision/recall, provenance accuracy, correction burden | Agent claim promoted as fact |
| Authority | canonical precision, stale-memory rate, conflict handling | Superseded truth used as current |
| Retrieval | recall@k, nDCG@k, citation correctness, dependency coverage | Relevant evidence omitted or noisy |
| Context pack | critical-fact coverage, relevance, token efficiency, actionability | Pack is technically relevant but unusable |
| Ask Shoo | factuality, citation entailment, fact/inference/suggestion labeling | Chatbot-like unsupported answers |
| Durability | Manual success/latency, idempotency, restore/verifiability | False durability promise |
| Resilience | offline recovery, out-of-order/duplicate convergence, provider outage | Coding blocked or silent data loss |
| Security | cross-tenant disclosure, secret egress, delegate/revocation behavior | High-impact trust failure |

## Core formulas

- Capture completeness = required normalized events observed / required events generated by the fixture.
- Extraction precision/recall are macro-averaged by memory type so common progress events do not hide poor decision/blocker performance.
- Canonical stale-memory rate = current-truth outputs containing superseded/deprecated memory / current-truth outputs.
- Citation correctness requires source identity, accessible scope and entailment; a clickable but non-supporting source fails.
- Token efficiency = rubric-weighted useful context tokens / total context-pack tokens.

## Test corpus matrix

The corpus must cross:

- client path: OpenCode→OpenCode, OpenCode→Codex, Codex→Codex when capture coverage exists;
- lifecycle: clean completion, checkpoint, crash, offline, context exhaustion;
- truth state: verified fact, agent claim, accepted decision, superseded decision, unresolved conflict;
- project shape: small, medium, multi-module;
- failure: duplicate, reorder, delayed cloud, unavailable model, unavailable MemWal/Walrus, revoked delegate;
- sensitivity: public fixture, secret-shaped decoy, restricted path, deletion/tombstone.

## Evaluation protocol

1. Freeze dataset, schemas, ranker configuration and scoring rubric.
2. Run deterministic non-model tests first.
3. Run model-dependent trials at least three times with recorded provider/model/version.
4. Score blind to candidate configuration where human judgment is required.
5. Report macro metrics, critical-type slices and worst-case failures—not averages alone.
6. Keep a sealed regression set that developers do not tune against.
7. Any model/embedding/ranker change reruns compatibility and regression gates.

## Failure triage

- P0: cross-tenant disclosure, plaintext secret egress, false canonical claim, unrecoverable accepted-memory loss.
- P1: critical omission blocks resume, wrong supersession, citation contradicts claim, incorrect durable-confirmed state.
- P2: non-critical noise, degraded ranking, recoverable latency failure.

P0 blocks release regardless of aggregate score. P1 consumes the quality error budget and requires root-cause classification by capture, extraction, authority, retrieval, generation or UI.
